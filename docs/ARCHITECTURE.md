# dsh-memory 结构整理方案

这个插件的功能一直在长，但没有一张图说明**什么东西管什么**。这份文档就是那张图。
目标不是重写代码，而是让每个功能有明确归属，以后加东西知道往哪放。

---

## 一、功能全景

| 功能 | 干什么 | 入口 | 配置项 |
|---|---|---|---|
| 记忆库 | 记录对话、工具调用、子代理，整理成记忆卡，按相关度注入 | 面板「记忆库」 | `capture`、`normalize`、`inject*` |
| 人格 | 给助手一套说话方式，可在面板切换 | 面板「人格」 | `persona` |
| 模型策略 | 记住本地模型和云端模型，支持相互切换 | 面板「模型」 | `modelPolicy` |
| 本地模型开关 | 每轮对话结束后切回本地模型 | 面板「QQ 通道」 | `qq.localSwitch`、`qq.localModel` |
| QQ 通道 | 通过界面自动化在 QQ 里收发消息 | 面板「QQ 通道」 | `qq.enabled`、`qq.userUin`、`qq.botUin` |
| QQ 指令 | 用固定命令查/切模型，不经模型 | QQ 聊天 | `qq-commands.js` |
| 语音合成 | 把回复变成语音文件（QQ 语音回复用） | 无面板 | `voice.js` |
| 主动问候 | 按活跃习惯在合适时间主动说话 | 面板「主动」 | `proactive*` |
| 观察下载 | 下载目录有新文件时提一句 | 面板 | `observe` |
| 备份/导入 | 导出记忆库，导入其他机器的数据 | 面板 | `backup*` |

## 二、命令表（唯一来源：qq-commands.js）

命令是**固定表**，精确匹配。说错了就是普通聊天，不会"猜"。

### 查询类

| 发送 | 返回 |
|---|---|
| `命令` / `帮助` / `？` / `?` | 全部命令列表 |
| `状态` / `模式` | 当前模型、自动切换、付费模型槽 |
| `模型列表` | 全部本地模型 + 付费 API 模型，标类型/计费 |
| `本地模型` / `付费模型` | 兼容旧写法，返回完整模型列表 |

### 控制类

| 发送 | 效果 |
|---|---|
| `开启自动切换本地模型` | 打开"每轮结束切本地" |
| `关闭自动切换本地模型` | 关闭 |
| `切换模型 <名字>` / `切到 <名字>` | 切到本地或 API 模型（必须在模型列表里） |
| `切回付费模型` | 回到上次使用的付费模型；没有记录则用付费槽 |

规则：
- 长度超过 40 字不作为命令
- 只有 `切到 X` 带参数；其他命令一个字都不能多
- 每条命令都回执，成功说结果，失败说原因

## 三、面板结构建议（从上到下）

1. **记忆库** — 统计、导出、刷新
2. **QQ 通道** — 连接状态、机器人号、你的号、启用开关
3. **模型** — 本地模型、云端模型、"每轮切本地"开关
4. **人格**
5. **其他** — 观察、备份、导入

原则：
- 一张卡片一个领域，不再把模型开关塞进 QQ 卡片
- 所有"选模型"统一在「模型」卡片里，QQ 卡片只引用结果
- 状态类信息（在线/离线/当前模型）放在各自卡片顶部

## 四、数据流

```
QQ 消息
  ↓ (qq-bridge 轮询 UI 自动化)
判断是不是指令 ──是──→ qq-commands 回执 ──→ sendQq 发回
  ↓ 否
投递到 DSH 会话（schedule.create）
  ↓
助手回复（assistant/message）
  ↓ (回复窗口内)
sendQq 发回 QQ

每轮结束（turn/end）
  ↓ (qq.localSwitch 打开时)
切回本地模型
```

## 五、代码文件职责

| 文件 | 职责 |
|---|---|
| `index.js` | 组装：注册工具/路由/监听，启动 QQ 桥接 |
| `qq-bridge.js` | QQ 轮询、去重、投递、发回复、窗口恢复 |
| `qq-commands.js` | **命令表（唯一来源）**，纯函数，可单测 |
| `scripts/qq-*.ps1` | 界面自动化原语：恢复窗口、定位会话、读消息、发消息、隐藏窗口 |
| `voice.js` | 语音合成（QQ 语音回复用） |
| `stt.js` | 语音识别（QQ 语音消息用） |
| `models.js` | 模型策略读写、切换 |
| `store.js` | 记忆库存储（SQLite） |
| `capture.js` / `inject.js` / `normalizer.js` | 记忆的采集、注入、整理 |
| `routes.js` | 面板数据、配置保存、导出 |
| `client.js` | 面板 UI |
| `runtime.js` | 数据库路径、模型调用封装 |

## 六、加新功能的规则

1. **新命令** → 只改 `qq-commands.js`，加进固定表 + 测试
2. **新面板开关** → `routes.js` 存 `qq.*` meta，`client.js` 加卡片，`index.js` 读
3. **新自动化动作** → 新增 `scripts/qq-*.ps1`，Node 侧只调用
4. **新功能领域** → 独立文件，不在 `index.js` 里堆逻辑

## 七、已知限制

- QQ 窗口在托盘时无法探测未读，只能周期性恢复窗口检查（会闪一下，无焦点）
- 聊天头名字 UIA 读不到，无法确认"当前会话是不是你"，只能定期重新定位
- QQ 语音消息需要 SILK 编码，ffmpeg 不支持编码，语音回复暂未打通
