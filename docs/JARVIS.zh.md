# 低配版贾维斯 · 缺口分析

目标：**能像人一样陪聊 + 能解决实际问题 + 尽量不花 token**。

这份文档只做一件事：把"现在有什么、还差什么、先补哪个"摆清楚。省 token 是排序标准，
不是口号——每一项都标了它省不省 token。

---

## 1. 已经有的

| 能力 | 状态 |
|---|---|
| 记忆（完整对话 / 实体 / 习惯 / 风格） | ✅ |
| 人格 + 关系（认识多久、称呼、边界） | ✅ |
| 时间感 + 每日状态 | ✅ |
| 陪聊模式（不主动干活、不主动提工作） | ✅ |
| 主动问候（时间跟随习惯） | ✅ |
| 住在电脑里（身体感） | ✅ |
| 工具（读写文件、跑命令、搜索、子代理、定时） | ✅（DSH 提供） |
| 按需检索 `memory_search` | ✅ |

**结论：人格和记忆这一层基本齐了。缺的全在"行动"和"省 token"这两块。**

---

## 2. 缺口清单（按省 token 价值排序）

### A. 本地优先的模型路由 ← **已落地**

"省 token"不是让模型变便宜，而是**默认用本地的，只有必要时才花付费的钱**。

已完成（`models.js` + 面板「本地模型」）：

| 行为 | 实现 |
|---|---|
| 读出本机所有 Ollama 模型 | `GET /api/tags`，面板列名字和体积 |
| 选一个作为本地模型 | 存 `store_meta.modelPolicy`，立刻 `agentDefaultModel.saveSelection()` |
| 回复完自动切回本地 | 插件启动时切一次 + 每轮 `turn/end` 切一次 |
| 只在必要时刻用云端 | 面板"这轮用云端"按钮；一轮之后自动回来 |
| 没有本地模型时 | 不切，保持 DSH 自己的设置 |

**诚实说明**：DSH 没有"改当前会话模型"的接口，只有"改默认模型"（`agentDefaultModel`）。
所以这是**对下一轮/新会话生效**的路由；已经开始的会话不会中途换脑。

### A2. 意图路由（仍然缺）

本地直答（0 token 回答"关于我的事"、或直接执行固定指令）还没做——这是下一步最大的一块。

### B. 本地技能库（干活的手脚）

贾维斯得能碰电脑。现在能跑命令，但要模型来想"跑什么"。有了路由之后，这些应该是一句话直达：

| 类别 | 具体动作 |
|---|---|
| 应用 | 启动程序、切窗口、关窗口 |
| 系统 | 音量、亮度、电源、网络、磁盘、进程 |
| 文件 | 整理下载目录、按类型归档、批量重命名、找文件 |
| 桌面 | 截图、读剪贴板、写剪贴板 |
| 媒体 | 播放 / 暂停 / 下一首 |

全部本地执行，**不消耗 token**。缺的是这张表 + 几个 PowerShell/COM 封装。

### C. 记忆直答（0 token 回答"关于我的事"）

现在这些也要过模型。其实答案直接在库里：认识多久、最常用词、最近聊了什么、某个对象的历史。
做一个 `askMemory(question)` 的本地模板层，命中就是 0 token。

### D. 注入优化（省 token 的细水长流）

现在每轮都注入记忆（160–520 token）。可优化：

- **只在话题切换或新会话时注入**，连续同话题跳过
- 注入"指针"而不是内容："细节可用 memory_search 查"（一句 15 token 换掉 200 token）
- 陪聊模式下注入关系/状态，不注入工作对象（这个行为已经由规则控制，但注入仍偏宽）

### E. 成本仪表盘

面板现在只显示"上次注入了多少 token"。应该显示：

- 今天本地处理 N 条（0 token）
- 今天模型处理 M 条（约 X token）
- 省下的比例

没有这个数字，"省 token"就只是感觉。

### F. 语音（本地，不花 token 但花 CPU）

贾维斯没有声音不像贾维斯：

- **STT**：whisper.cpp（ggml-base/small，CPU 可跑，约 150MB）
- **TTS**：Windows SAPI（系统自带，零依赖）；要更好听上 edge-tts（需联网）

代价：麦克风常驻、CPU 占用、误唤醒。**建议做成手动按住说话，而不是全程待机。**

### G. 主动观察（主动但不烦）

现在只有定时问候。可以加：

- 下载目录出现新文件 → 一句"下好了"
- 日程快到（schedule 已有）
- 长时间没动静 → 不打扰（本地判断）

关键原则：**本地判断，必要时才叫模型**。

### H. 任务编排（一条命令干一串事）

"把桌面截图整理进文件夹并压缩"现在要模型多轮。贾维斯应该有本地脚本编排（一个 PowerShell 函数搞定），
模型只在"用户意图不明确"时介入。

### I. 安全闸（无审查模型的必需品）

你现在是"从不询问审批" + 无审查模型。危险动作必须在**本地硬拦**：

- 删除、覆盖、关机、格式化、改注册表 → 一律要确认（不看模型脸色）
- 建议给技能库分级：`safe` / `ask` / `deny`

### J. 长期巩固（P5）

每周把对话压成"关系叙事"（本地小模型或规则），避免每次翻细节找上下文。

## 3. 建议顺序

| 顺序 | 内容 | 省 token | 体验提升 | 估时 |
|---|---|---|---|---|
| 1 | **意图路由 + 0 token 直答** | ★★★ | ★★★ | 2–3 天 |
| 2 | **本地技能库（Windows 动作）** | ★★★ | ★★★ | 2–3 天 |
| 3 | 注入优化（指针化 / 话题切换才注入） | ★★ | ★ | 1 天 |
| 4 | 成本仪表盘 | ★★ | ★★ | 半天 |
| 5 | 安全闸（技能分级） | — | ★★ | 半天 |
| 6 | 语音（STT + TTS） | ★ | ★★★ | 2 天 |
| 7 | 主动观察 | ★ | ★★ | 1 天 |
| 8 | 长期巩固 | ★ | ★ | 1 天 |

---

## 4. 诚实的边界

1. **闲聊本身省不掉 token**。想"像人"就得过模型，能省的只是"重复问答、固定指令、简单操作"。
2. **"低配贾维斯"的现实目标**：日常常见指令 0 token → 闲聊 1 次调用 → 复杂任务多轮。
   宣称"完全不用 token"是骗人的。
3. **语音需要额外依赖**，且会持续占 CPU；按住说话比全程待机实际。
4. **无审查 + 无审批 = 危险**。技能库分级不是可选项，是前置条件。

---

## 5. 一句话总结

**人格和记忆已经不缺了；缺的是"嘴替手"——一个在模型前面挡掉 80% 日常请求的本地层。**
先做 A + B，日常使用就能从"每句话都花钱"变成"偶尔才花钱"。
