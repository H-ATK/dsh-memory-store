# 记忆库

把所有工作区的对话、工具调用和子代理运行记录进一个本地 SQLite 记忆库，由所有会话共享；再把命中的记忆在模型开始思考前放回上下文。

## 界面在哪

两个入口，内容相同：

- **设置 → 记忆库**：完整页面。
- **插件 → 记忆库 → 插件页介绍下方**：同一套面板。

面板是只读浏览加人工纠正：

- 顶部统计：记忆对象、出现次数、已记录轮次、工具调用、待整理条数。
- 「最近一次注入」显示上一次注入放进了几条记忆、多少 token、涉及哪些对象。
- 对象列表：名称、类型、最后动作/状态/细节、累计次数与最近日期。
- **「合并…」** 把一条对象并入另一条，次数累加。合并保留每条原始指针，所以不会丢数据。
- 「最近出现」是时间线；输入框按名称筛选。

## 它记录什么

| 来源 | 记录内容 |
|---|---|
| 用户输入 | 异步整理成记忆卡片：对象、类型、动作、状态、细节 |
| 助手回复 | 每轮最终文本的摘要（不记录流式分片） |
| 工具调用 | 工具名、静态作用、本次做了什么、时间 |
| 子代理 | 每次运行一行：父会话、提供方、结果、耗时、最终答复摘要 |

**不记录**子代理的会话内容，也不保存你的原话——只保存 `(会话, 序号)` 指针，需要时可以按指针回到原句。

## 开销

- 首次启用会把历史会话回填一次（10 万条事件约 1.5 分钟，之后启动只处理新内容）。
- 每轮整理一次小模型请求，约 ¥0.0008；每小时最多 60 次，可用配置调低或关闭。
- 启动前注入的记忆约 170–280 token，预算上限 800，可在配置里改。

## 关掉会怎样

关掉 `normalize` 只停止整理，已有记忆仍在；关掉 `injectMemories` 只停止注入，模型不再自动看到记忆；关掉整个插件则停止记录，数据库文件保留，重新启用后继续累积。
